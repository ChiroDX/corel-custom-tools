The Four Components

Runs inside CorelDRAW

Makros/ — VBA

ApiClient.bas owns HTTP, auto-start and the Ping liveness sub. ShapeSerializer.bas turns a selection into ShapeExchange JSON; ShapeDeserializer.bas writes a result back. ToolsPanel.frm is the in-CorelDRAW UserForm.

Local service

ai-server/ — Node + Express 5

ESM, Node ≥ 20.6. Text, image and CorelDRAW-adapter routes, an in-memory session store, a WebSocket event stream, and a provider abstraction over OpenAI, Anthropic and Ollama. Binds to 127.0.0.1.

What the designer clicks

chiroDX-app/ — Electron 43 + React 19

A narrow always-on-top panel built with Vite 8. Sandboxed renderer, contextBridge-only IPC. It spawns the server on launch and drives CorelDRAW back through a COM bridge.

Fallback

Makros/ChiroDXTools.hta

A plain HTA panel that setup.bat copies to the config folder. It is what you double-click when Node or the Electron app will not start. Not the primary UI.

Session Lifecycle

StepActorWhat happens
pending VBA
  • SendSelection serializes the selection and POSTs /corel/push
  • Server stores the session and broadcasts selection-changed
  • Panel fetches /corel/selection/:id and renders the shapes
ready Panel
  • Designer runs a tool; the result is POSTed to /corel/result
  • Server broadcasts result-ready
applied VBA
  • ApplyResult — pressed in CorelDRAW, or triggered from the panel over COM
  • VBA GETs /corel/result/:id, merges shapes by shapeId
  • POSTs /corel/result/:id/applied; server broadcasts result-applied
cancelled Either
  • Dismissed from the panel, or evicted by the 30-minute sweep
  • Store keeps at most 200 sessions and evicts the oldest
  • Everything is in memory — a server restart drops all sessions

Two Decisions Worth Knowing

What shipped

Electron panel + local server

Electron 43 · React 19 · Vite 8 · Express 5 · VBA
  • Real UI: live selection view, results list, keyboard reachable
  • VBA stays thin — serialize, POST, deserialize
  • Async everywhere, so CorelDRAW never blocks on an AI call
  • Panel can drive CorelDRAW back via COM, no window switching
  • Server is reusable by the HTA fallback and by any other client
  • Floats above CorelDRAW; it is not a docked VSTA panel
  • Needs Node.js on the machine
  • Three moving parts to install rather than one

VSTA C# docker — not taken

C# · .NET · Visual Studio 2019 · WebView2
  • Truly dockable next to Objects and Properties
  • No separate server process to install or supervise
  • Pinned to one specific Visual Studio version
  • Compiled DLL — no quick edit, slower iteration
  • High setup friction on each designer's PC
  • Would not have removed the need for the VBA side anyway

Trade-off accepted: a floating panel that ships and can be changed in minutes beat a docked panel that needs a specific toolchain. The server boundary means the front end could still be replaced later without touching the VBA or the model layer.

Security Posture

SurfaceStatusControl
ai-server network exposure Loopback
  • Binds 127.0.0.1 unless HOST is set deliberately
  • No authentication — endpoints read local files, so it must stay local
  • CORS is open on purpose: the COM host has no origin
Electron renderer Isolated
  • contextIsolation: true, nodeIntegration: false, sandbox: true
  • preload.js exposes named wrappers only — no channel is caller-chosen
  • will-navigate and setWindowOpenHandler both deny
  • CSP in index.html; object-src, base-uri, form-action all none
IPC arguments Validated
  • shell.openExternal — http:/https: only, so no file: or handler abuse
  • Reveal-in-Explorer — chiroDX_* inside the OS temp folder only
  • Macro and GMS names must match a strict VBA identifier pattern
  • Clipboard writes capped at 1,000,000 characters
Request input Bounded
  • Session IDs restricted to [A-Za-z0-9_-]{1,64}
  • Push capped at 500 shapes, body at 10 MB
  • Every upstream model call bounded at 60 s, two retries
  • 5xx detail stays on the console; clients get a short message
CustomMacroStorage.gms Opaque
  • Binary — cannot be reviewed in a diff
  • The reviewable logic lives in the exported .bas modules
  • VBA cannot be compiled or tested in CI; changes are verified by hand

Where The Project Stands

✓
Phase 1 — Single repo Done
chatgpt-corel merged into ai-server/. One repo, one lockfile, .env gitignored.
✓
Phase 2 — General AI server Done
Route modules, /health, CORS, a provider abstraction with a model setting, shared validators, and a global error handler that never leaks provider internals. Covered by a node:test suite.
✓
Phase 3 — The panel Done
Built as Electron + React rather than a VBA UserForm. Sections for Selection, Text, Image & Colour, Font and Settings, with a results list. The VBA ToolsPanel.frm and the HTA remain as fallbacks.
✓
Phase 4 — Context awareness Done
The full selection travels as structured JSON: shapes, paragraphs, runs, fonts, sizes, colours and bounds. The panel renders it live over a WebSocket, so the tools operate on what is actually selected.
✓
Phase 5 — Write-back loop Done
Results return as ShapeResult and are merged by shapeId. ApplyResult can be triggered from CorelDRAW or from the panel over COM. The loop is closed.
6
Phase 6 — Direct formatting write-back Next
Today "Apply" for a text fix copies to the clipboard rather than patching the run in place. Applying font, size and colour changes per run — the format the spec already describes — is the next real step.
7
Phase 7 — Auto-layout from data Later
Generate a laid-out menu from a JSON file matching specs/menu-data-model.ts — text frames, tab stops, superscript allergens, price columns. The largest remaining idea, and the reason that spec exists.
